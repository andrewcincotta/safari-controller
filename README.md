# safari-controller
Adds a few must-needed features to Safari to increase productivity.

## Features

- **Rename windows.** Give any Safari window a fixed name, so its title stops changing with whichever tab is active. Clear the name to go back to Safari's default behavior.
- **Move tabs between windows.** Send any tab to any other open window, or to a new window. You can do this from the toolbar popup (the "Move to…" menu or drag-and-drop) or from the page's context menu (**Move Tab to Window ▸**).

## Layout

```
extension/          The web extension (Manifest V3). All behavior lives here.
  manifest.json
  background.js     Window-name store, title syncing, tab moves, context menu
  content.js        Pins a tab's document.title to its window's name
  popup.html/.css/.js
  shared.js         Message types and helpers used by all of the above
  images/           Icons (generated by scripts/make-icons.swift)
xcode/              macOS host app + Safari extension target (generated by
                    safari-web-extension-converter). It references extension/ in place.
scripts/            Dev utilities
```

## Building and running

1. Open `xcode/Safari Controller/Safari Controller.xcodeproj` in Xcode.
2. Choose your team under *Signing & Capabilities* for both targets, or run unsigned (see step 4).
3. Build and run the **Safari Controller** scheme. The host app opens and links to Safari's extension settings.
4. For unsigned local builds: in Safari, open **Settings → Advanced**, enable **Show features for web developers**, then go to **Develop → Developer Settings…** and turn on **Allow unsigned extensions**. You have to redo this every time Safari relaunches.
5. Enable **Safari Controller** in **Settings → Extensions**, and set its website access to **Allow on every website**. Window renaming needs this access (see below).

Edits to files in `extension/` take effect on the next Xcode build. You don't need to regenerate the project.

To regenerate the icons: `swift scripts/make-icons.swift extension/images`.

## How window renaming works

Safari has no API for setting a window's title. It always uses the title of the window's active tab. So the extension renames a window by pinning the active tab's `document.title` to the name you chose. The content script keeps the pinned title in place when the page tries to change it. Tab switches, tab moves and name changes pass the pin to the new active tab. Every other tab keeps its real title.

Trade-offs of this approach:

- The active tab's label in the tab bar also shows the window name.
- The name can't be shown when the active tab is a page extensions can't run on. That includes the Start Page, Safari's internal pages, other extensions' pages, and any site you haven't granted access to. While one of those is active, the window falls back to Safari's normal title.
- Window ids change each time Safari relaunches. Each name therefore stores a snapshot of its window's URLs. At launch, the name goes back to the restored window whose tabs best match that snapshot.

## Moving tabs

Moves use `tabs.move`, which keeps the page's state and history. If Safari refuses a direct move, the extension opens the URL in the destination window and closes the original. In that case the tab's back/forward history is lost. Tabs can't be moved between private and regular windows.

Safari doesn't let extensions add items to the tab bar's context menu. That's why the context-menu entry is on the page itself.
